Overview / Agent guidance

Agents

Agent guidance.

Use this when Codex, Claude Code, Copilot Agent mode, or another shell-capable agent is running xyte-cli for you.

Agent roleRun commands, inspect output, create files, and explain the next safe action.
Your roleProvide goals, tenant choice, key-file path, and approval before writes.
BoundaryNever paste secrets into chat. Never let an agent apply a write from a vague prompt.

What agents do

An agent should operate the same CLI a person would use. It should show the command it ran, use structured output when it needs to reason over results, and stop when the next step needs a human decision.

Workflow

  1. GoalUnderstand the taskStart from the operator outcome, not from a guessed endpoint.
  2. ReadyCheck setupConfirm CLI, tenant, and connectivity before interpreting data.
  3. ReadInspect current stateWatch incidents, inspect fleet, or describe endpoint contracts.
  4. GatePlan writesShow the proposed change and wait for explicit approval.
  5. HandoffReport pathsList commands run, files written, and the next safe action.

Ask an agent

Use short, plain requests. Do not preload the prompt with IDs unless you already have them. Let the agent discover context and ask only for missing inputs.

Show me whether xyte-cli is ready for this workspace.

Show me active incidents and the fleet context for the ready tenant.

Create today's fleet report. Save the source JSON and tell me the report path.

Help me plan remediation for the current issue, but stop before apply.

Terminal and CI

The same work should be reproducible without an agent. In a terminal, run the command directly. In CI, use non-interactive setup, JSON output, saved artifacts, and plan-only flows unless the job has a separate approval step.

# Terminal
xyte-cli ops inspect fleet \
  --tenant <tenant-id> \
  --render json \
  --out ./artifacts/fleet.json

# CI
printf "%s" "$XYTE_CLI_KEY" | npx -y @xyteai/cli@latest setup run \
  --non-interactive \
  --tenant <tenant-id> \
  --key-stdin \
  --format json

npx -y @xyteai/cli@latest flow run flow.daily-deep-dive-report \
  --tenant <tenant-id> \
  --plan \
  --strict-json

Setup path

When setup is missing, the agent should ask for a tenant id and a path to an API key file outside the workspace. It should not ask for the key text.

xyte-cli doctor environment --format json
xyte-cli setup run \
  --non-interactive \
  --tenant <tenant-id> \
  --key-file <path-outside-workspace> \
  --format json
xyte-cli setup status --tenant <tenant-id> --format text
xyte-cli init --scope project --agents all --force --no-setup

Write boundary

For commands that can change tenant state, the agent should plan first. Apply is a separate step after the operator reviews the target, effect, and resume path.

xyte-cli flow run <flow-id> --tenant <tenant-id> --plan
xyte-cli flow run <flow-id> --tenant <tenant-id> --apply --resume <run-id-or-path>
  • Read-only requests can run immediately after readiness checks.
  • Move, claim, close, update, send-command, and import actions need approval.
  • After a write, the agent should read back the changed state.

Real-life examples

Morning support handoff

Ask: "Show me what changed in active incidents since yesterday and save fleet context." The agent runs watch once, saves fleet JSON, and summarizes changes.

Weekly operations report

Ask: "Create this week's deep-dive report for the ready tenant." The agent saves source JSON and a Markdown or PDF report.

Room reorganization

Ask: "Help me move devices after the room import." The agent exports current devices and spaces, builds a move CSV, and stops at dry run.

Edge onboarding

Ask: "Help me claim these Edge devices from the spreadsheet." The agent prepares rows, explains rejects, runs plan, and waits before apply.

Handoff

A useful agent answer should end with what changed, what did not change, where the files are, and what the next decision is.

Ready tenant: <tenant-id>
Commands run: setup status, config doctor, ops inspect fleet
Files written:
  ./artifacts/fleet.json
  ./reports/xyte-daily.md
Next action: review the report or ask for remediation planning.
