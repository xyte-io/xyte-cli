Guides / Setup and readiness

Setup

Setup readiness.

Use this before any operational workflow. It confirms that the CLI runs, the tenant key is connected, and the tenant can answer basic API checks.

Use whenNew machine, new tenant, or first command in an agent session.
InputsA tenant id or alias, plus an API key file only when setup is missing.
OutputReady tenant status and connectivity diagnostics.

Ask an agent

Paste a direct request. The workflow below shows what the agent should check behind the scenes.

Show me whether xyte-cli is ready for operations.

Use the configured tenant if one is ready. If there are several, ask me which one.
If setup is missing, ask for the tenant id and the path to an API key file outside this workspace.
Do not ask me to paste a secret into chat.
Stop once you can show CLI status, tenant readiness, connectivity, and anything blocking operational commands.

Workflow

  1. StartCheck the CLIConfirm the command can run in this environment.
  2. TenantFind readinessUse an existing ready tenant or ask which one to connect.
  3. SecretConnect keyRead the key from a file only when setup is missing.
  4. DoctorTest accessRun readiness and connectivity checks for the selected tenant.
  5. ReadyStop cleanlyReport what is ready and what still blocks operations.

If the agent cannot run shell commands, use the Terminal Commands view instead.

Goal

A complete setup result means three things: the command resolves on PATH, the key is stored outside the repository, and the tenant reports ready before you run fleet, incident, Edge, or report commands.

Commands

  1. Check the local command environment

    Start here even if you think the CLI is installed. The doctor tells you whether to use the installed binary, npx, or a workspace-local install.

    xyte-cli doctor environment --format text
xyte-cli doctor install --format text
xyte-cli --version

  2. Connect a tenant key without exposing the secret

    Create the API key in Xyte and save it in a plain text file outside the project folder. Do not paste it into chat or commit it to the repo.

    xyte-cli setup run \
  --non-interactive \
  --tenant <tenant-id> \
  --key-file <path-outside-workspace> \
  --format json

  3. Confirm readiness and connectivity

    Run both checks. setup status reads the configured tenant; config doctor checks whether the key can actually reach the service.

    xyte-cli setup status --tenant <tenant-id> --format text
xyte-cli config doctor --tenant <tenant-id> --format text
xyte-cli status --tenant <tenant-id> --mode fast --format json

Read the output

  • setup status should show the tenant profile and that setup is ready.
  • config doctor should report connected. If it does not, fix this before using operational commands.
  • status --mode fast gives a compact machine-readable readiness result for scripts and agents.
Tenant: <tenant-id>
State: ready
Connectivity: connected
Missing setup: none

You are done when the tenant is ready and connectivity is connected. If either value is missing or failed, stop here and fix setup before moving to incidents, reports, or Edge workflows.

If it fails

xyte-cli is not found

Run npx -y @xyteai/cli@latest doctor environment --format json and use the command recommended in the report.

Tenant is not ready

Run setup again with the intended tenant id and key file. Confirm you did not use a partner key for an organization tenant or the reverse.

Connectivity fails

Check network access, key scope, and provider selection. If you are intentionally offline, run setup with an explicit provider and --connectivity never.
