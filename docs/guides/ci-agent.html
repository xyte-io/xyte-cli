Automation

CI and agents.

Use this when Xyte checks or reports need to run without a person typing every command: scheduled jobs, pipeline checks, or shell-capable agents such as Codex, Claude Code, and Copilot Agent mode.

Ask an agent

Ask like this when the job does not exist yet. The agent should learn the job purpose before it writes configuration.

Use xyte-cli to set up a repeatable CI or agent job for fleet reporting.

What the agent will do

  1. DiscoverDefine jobClarify the report, plan, schedule, runtime, and saved artifacts.
  2. InspectCheck runtimeConfirm Node, CLI package, tenant setup, and secret source.
  3. ChoosePick surfaceSelect GitHub Actions, GitLab CI, Jenkins, a flow alias, or an agent runbook.
  4. StopShow draftPresent the job shape before writing files or creating flows.
  5. ReturnHandoffShow commands, artifacts, rerun path, and where apply requires approval.

Ask how it works first

The agent can explain CI setup, secret handling, and artifacts before it writes workflow configuration.

Goal

Automation should be explicit about where the API key comes from, which local profile is used, and whether the command is read-only or write-capable. Use JSON output for machines and plan mode before writes.

CI recipes

These jobs are no-write by default. They set up the CLI from XYTE_CLI_KEY, create artifacts, and run read-only or plan-only commands with pinned @xyteai/cli@0.11.0.

  1. GitHub Actions

    Add a repository or environment secret named XYTE_CLI_KEY. Use XYTE_PROFILE only when the runner manages more than one Xyte connection.

    name: xyte-readiness
on:
  workflow_dispatch:
  schedule:
    - cron: "15 6 * * *"
jobs:
  xyte:
    runs-on: ubuntu-latest
    env:
      XYTE_CLI_KEY: ${{ secrets.XYTE_CLI_KEY }}
      XYTE_PROFILE: default
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "22"
      - run: mkdir -p artifacts reports
      - run: |
          printf "%s" "$XYTE_CLI_KEY" | npx -y @xyteai/cli@0.11.0 setup run \
            --non-interactive \
            --tenant "$XYTE_PROFILE" \
            --key-stdin \
            --format json
          npx -y @xyteai/cli@0.11.0 config doctor --tenant "$XYTE_PROFILE" --format json \
            > artifacts/xyte-doctor.json
          npx -y @xyteai/cli@0.11.0 ops inspect fleet \
            --tenant "$XYTE_PROFILE" \
            --render json \
            --strict-json \
            --out artifacts/xyte-fleet.ci.json
      - uses: actions/upload-artifact@v4
        with:
          name: xyte-artifacts
          path: |
            artifacts/
            reports/

  2. GitLab CI

    Add a masked CI/CD variable named XYTE_CLI_KEY. Set XYTE_PROFILE to default unless the runner manages multiple connections.

    xyte_readiness:
  image: node:22
  stage: test
  script:
    - mkdir -p artifacts reports
    - |
      printf "%s" "$XYTE_CLI_KEY" | npx -y @xyteai/cli@0.11.0 setup run \
        --non-interactive \
        --tenant "${XYTE_PROFILE:-default}" \
        --key-stdin \
        --format json
    - npx -y @xyteai/cli@0.11.0 config doctor --tenant "${XYTE_PROFILE:-default}" --format json > artifacts/xyte-doctor.json
    - npx -y @xyteai/cli@0.11.0 ops watch incidents --tenant "${XYTE_PROFILE:-default}" --profile incidents-active --once --strict-json --out artifacts/incidents.ndjson
  artifacts:
    when: always
    paths:
      - artifacts/
      - reports/

  3. Jenkins

    Store the API key as a secret text credential. Use a plain environment value for the profile label only when this runner manages multiple Xyte connections.

    pipeline {
  agent any
  tools { nodejs "node-22" }
  environment {
    XYTE_PROFILE = 'default'
  }
  stages {
    stage('xyte readiness') {
      steps {
        withCredentials([string(credentialsId: 'xyte-cli-key', variable: 'XYTE_CLI_KEY')]) {
          sh '''
            mkdir -p artifacts reports
            printf "%s" "$XYTE_CLI_KEY" | npx -y @xyteai/cli@0.11.0 setup run \
              --non-interactive \
              --tenant "$XYTE_PROFILE" \
              --key-stdin \
              --format json
            npx -y @xyteai/cli@0.11.0 config doctor --tenant "$XYTE_PROFILE" --format json > artifacts/xyte-doctor.json
            npx -y @xyteai/cli@0.11.0 flow run flow.daily-deep-dive-report \
              --tenant "$XYTE_PROFILE" \
              --plan \
              --strict-json \
              --out-dir artifacts/flow-runs
          '''
        }
      }
    }
  }
  post {
    always {
      archiveArtifacts artifacts: 'artifacts/**, reports/**', allowEmptyArchive: true
    }
  }
}

CI decision table

SignalWhat it meansNext step
Empty secretXYTE_CLI_KEY is unset or unavailable to this branch.Fix CI secret scope; do not print the secret while debugging.
Auth failureThe key is wrong, expired, or belongs to the wrong provider scope.Create a new Xyte key and rerun setup. Force the provider only if your admin tells you to.
Blocked readinessDoctor cannot reach Xyte or setup is incomplete.Stop the job; run setup readiness before operational commands.
Active incidentsThe read job found current incidents.Keep artifacts and route to incident triage or a notification step.
Rejected rowsA utility preparation or batch plan found rows it will not run.Fix source data, rerun prepare, then rerun plan.
Paused flowA flow reached an approval gate.Publish the run bundle; apply only from an approved resume job.
Partial batchSome rows completed and others failed or were skipped.Use the same resume artifact and rerun only after fixing failed rows.
Network failureThe job could not reach Xyte or an Edge proxy.Retry after network checks; avoid apply retries without resume artifacts.
Write plan pendingThe job produced a change plan.Review target ids and effect; run apply in a separate approved path.

Agent prompt

Use a shell-capable agent. Chat-only assistants can explain commands, but they cannot install or run the CLI.

Use xyte-cli to set up a repeatable CI or agent job for fleet reporting.

Use the job result when it creates JSON artifacts, uses the intended profile, and ends read-only or at a plan gate. If the secret is missing, readiness is blocked, JSON artifacts are missing, incidents need handoff, or a write plan waits for approval, keep the job output attached and route the next step to a person.

Make this repeatable

# Environment
XYTE_CLI_KEY=<secret from CI, never from source>
XYTE_PROFILE=default

# Rerun path
printf "%s" "$XYTE_CLI_KEY" | npx -y @xyteai/cli@0.11.0 setup run --non-interactive --tenant "$XYTE_PROFILE" --key-stdin --format json
npx -y @xyteai/cli@0.11.0 ops inspect fleet --tenant "$XYTE_PROFILE" --render json --strict-json --out ./artifacts/xyte-fleet.ci.json

If it fails

The command is missing

Use the npx command or the workspace-local command recommended by doctor environment.

The secret is empty

Check the CI variable name and whether the job is allowed to read it for this branch or environment.

A parser fails on output

Use the command's JSON output option with --strict-json. Do not parse human-readable terminal text.

The agent wants to apply a change immediately

Stop it and ask for the plan output first. Apply only after the target ids and next action are clear.
