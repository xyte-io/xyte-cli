Guides / Device migration

Devices

Device migration.

Use this when a room plan, space import, naming cleanup, or tenant reorganization means devices must move to different spaces without guessing targets.

Use whenRooms were reorganized, imported, renamed, or split.
InputsThe source group, the intended target structure, and the field that should connect them.
OutputA move CSV, dry-run report, and apply report.

Ask an agent

Ask for the space-change outcome. The workflow turns that into discovered records, a move file, and a dry-run gate.

Help me move devices after a space change.

Use the ready tenant, or ask which tenant if more than one is ready.
Ask what changed, then find the source devices and target spaces.
Show the proposed move CSV and dry-run results.
Call out ambiguous rows.
Do not apply moves until I approve the dry run.

Workflow

  1. ChangeSpace movedStart from the room plan, import, rename, or split.
  2. DiscoverFind recordsRead source devices and target spaces from tenant state.
  3. MapBuild CSVCreate rows only when device and target ids are known.
  4. Dry runReview rowsCatch missing, duplicate, or weak matches before changes.
  5. ApplyMove and verifyApply approved rows and read device spaces back.

Goal

Device migration should be boring: collect source and target data, create a CSV, review the rows, dry-run, then apply. Do not move devices directly from a guessed spreadsheet.

Commands

  1. Export source devices and target spaces

    Use explicit filters so the move plan is scoped to the intended part of the tenant.

    xyte-cli api call organization.devices.getDevices \
  --tenant <tenant-id> \
  --query-json '{"space_id":"<source-space-id>","page":1,"per_page":100}' \
  > ./artifacts/source-devices.json

xyte-cli api call organization.spaces.getSpaces \
  --tenant <tenant-id> \
  --query-json '{"path_includes":"<target-path>","page":1,"per_page":100}' \
  > ./artifacts/target-spaces.json

  2. Create a proposed move CSV

    Start with name matching when device names and space names are intentionally aligned. If they are not, prepare the CSV manually.

    xyte-cli util match \
  --tenant <tenant-id> \
  --source ./artifacts/source-devices.json \
  --target ./artifacts/target-spaces.json \
  --source-field name \
  --target-field name \
  --out ./artifacts/device-moves.csv \
  --strict-json

  3. Dry-run the move plan

    Dry-run reports planned rows and row-level problems without moving anything.

    xyte-cli util move-devices \
  --tenant <tenant-id> \
  --input ./artifacts/device-moves.csv \
  --report ./artifacts/device-migration.dry-run.ndjson

  4. Apply reviewed rows

    Apply only after checking the CSV and dry-run report.

    xyte-cli util move-devices \
  --tenant <tenant-id> \
  --input ./artifacts/device-moves.csv \
  --apply \
  --report ./artifacts/device-migration.apply.ndjson

Review the plan

  • Every row should have a known device_id and target_space_id.
  • Remove rows where the target was guessed from a weak name match.
  • Keep dry-run and apply reports separate so you can compare planned versus executed rows.
  • After apply, inspect the moved devices rather than assuming the command output is the final tenant state.
device_id,target_space_id,device_name,target_space_name
<device-id>,<space-id>,"Room 101 Display","HQ / Floor 1 / Room 101"

You are done when the apply report has no failed rows and the moved devices read back with the expected space_id.

If it fails

Duplicate or weak matches

Edit the CSV directly or rerun matching with a better source or target field.

Invalid target space

Re-export spaces and replace the target ids before applying.

Some rows fail during apply

Fix only the failed rows and rerun. Use --continue-on-error only when partial completion is acceptable.
