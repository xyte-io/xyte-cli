Install

Start with a short, credible path to value.

Lead with the core install commands, then connect the tenant key, verify readiness, and move into watch or reporting flows. The commands stay visible so evaluators can judge what the tool is actually doing.

Core install

npm install -g @xyteai/cli@latest
xyte-cli install --skills
xyte-cli --version
Open npm package

Then connect and verify

  • Connect the tenant key once. Use the current non-interactive setup path so the environment is ready for future runs. XYTE_CLI_KEY="<key>" xyte-cli setup run --non-interactive --connectivity auto
  • Check readiness in JSON. Read the tenant context back out before moving into watch or reporting commands. xyte-cli setup status --format json

What evaluators should see

  • Install does not hide the real commands. The homepage makes the executable path obvious instead of burying it in prose.
  • Read-oriented workflows are the first experience. Incident watch, deep-dive export, and PDF reporting are the lead use cases.
  • Advanced reference still exists. Commands, flows, and schemas are linked out instead of taking over the landing page.

Next commands

xyte-cli watch --tenant <tenant-id> --profile incidents-active --once
xyte-cli inspect deep-dive --tenant <tenant-id> --window 24 --format json > deep-dive.json
xyte-cli report generate --tenant <tenant-id> --input deep-dive.json --out fleet-report.pdf

How it works

Keep the operator path explicit from start to handoff.

The product story is not just “there is a CLI.” It is a repeatable path: install, prepare the agent environment, connect safely, then move into incident visibility and reportable artifacts.

01

Install for people and agents

Use the npm package directly, then install skills for Codex, Claude, and Copilot in the same workspace.

xyte-cli install --skills
02

Connect tenant context once

Use setup status as the explicit contract for readiness instead of assuming hidden local state.

xyte-cli setup status --format json
03

Inspect incidents without surprise writes

Start with watch and inspection flows so evaluators understand the read-first posture before any mutation.

xyte-cli watch --profile incidents-active --once
04

Produce artifacts other teams can consume

Deep-dive JSON and PDF reports make the workflow useful outside the terminal, not just inside it.

xyte-cli report generate ...
