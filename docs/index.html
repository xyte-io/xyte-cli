Install

Start with a short, credible path to value.

Lead with the core install commands, then connect the tenant key, verify readiness, and move into inspection, console, or reporting flows. The commands stay visible so users can judge what the tool is actually doing.

Core install

npm install -g @xyteai/cli@latest
xyte-cli init
xyte-cli --version
Open npm package

Then connect and verify

  • Connect the tenant key once. Use the current non-interactive setup path so the environment is ready for future runs. XYTE_CLI_KEY="<key>" xyte-cli setup run --non-interactive --connectivity auto
  • Check readiness in JSON. Read the tenant context back out before moving into watch or reporting commands. xyte-cli setup status --output json

What public users should see

  • Install does not hide the real commands. The homepage makes the executable path obvious instead of burying it in prose.
  • Read-oriented workflows are the first experience. Inspection, deep-dive export, console access, and PDF reporting are the lead use cases.
  • Advanced reference still exists. Commands, flows, and schemas are linked out instead of taking over the landing page.

Next commands

xyte-cli ops watch incidents --tenant <tenant-id> --profile incidents-active --once
xyte-cli ops inspect deep-dive --tenant <tenant-id> --window 24 --output json > deep-dive.json
xyte-cli ops report generate --tenant <tenant-id> --input deep-dive.json --out fleet-report.pdf
xyte-cli ops console --screen dashboard

Terminal watch is human-readable by default. Agents should add --strict-json.
